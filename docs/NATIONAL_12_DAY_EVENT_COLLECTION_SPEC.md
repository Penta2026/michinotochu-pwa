# 全国道の駅イベント収集 — 初回10〜12日・継続日次運用仕様
更新: 2026-10-15

## 目的と達成基準

1. アプリの登録済み道の駅 **1,234駅** を固定の母集団とし、**初回10〜12日程度**で全国の公式情報源を一次巡回することを狙う。
2. 国の登録駅一覧と全国連絡会の公開名簿を参照して、一意の県名・駅名で駅を照合する。重複駅名や別施設の誤結合は不採用。
3. 駅別の公式ウェブサイト／運営者候補を発見し、駅名の確認、イベントらしいリンクの発見、開催情報の厳密な検査を自動連携する。
4. **イベントが載っていない駅も、ページが取得できない駅もあるため、全国イベントの完全取得は保証しない。** 調査が済んだ駅数をイベント掲載駅数と混同しない。
5. 一巡後も新着情報を日次継続。利用者の端末は全国JSONを手動で更新してローカル保存できる。端末側に全国スクレイピングをさせない。

## GitHub Actions 処理順序（日本時間）

| 時刻 | ステップ | 上限 | 公開データ |
|---|---|---:|---|
| 午前3時 | 全国名簿の未調査駅を調べる | 96駅/日 | 駅の照合結果のみ |
| 同一処理 | 公式サイト候補の一次検査 | 120サイト/日 | 候補と監査のみ |
| 同一処理 | 前段の候補サイトで個別イベント記事を調査 | 60駅/日・1駅3ページ以内 | 厳格条件合格のみステージング |
| 同一処理 | 全国一次巡回ダッシュボード生成 | 1,234駅台帳 | 調査進捗のみ |
| 午前6時 | 地域別の従来収集器＋厳格検証済み候補を統合 | 既存品質監査 | `data/road_events.json` |

GitHub Actions の起動・サイトの応答遅延は一定ではない。成功した日だけ巡回済みとして計上し、失敗日は必ず記録する。96駅/日の理論値はスループットの目安であって、10〜12日の達成保証ではない。

## 自動検証・情報源保護

- 全国公式名簿に載り、同一駅ID・県名・名称に一致した候補リンクのみ審査キューへ進める。
- URLがHTTPS、同一ホストで、リダイレクト先を無断で追跡せず、robots.txt が許すページだけ取得する。
- 公式名簿からの紹介URLや、ページ本文内の駅名一致は**所有権の確定ではない**。審査ログでは未確認として保持する。
- イベント公開候補には、一つの明確なイベント名、記事本文中の**西暦付き開催日**、**「会場」「開催場所」等の見出しと道の駅名の一致**が必須。
- 投稿日、応募締切、期間不明のカレンダー、別会場、終了済み、記事一覧、曖昧な複数行事、開催中止は採用しない。
- 抽出に成功した候補であっても、日次の全国品質検査・重複照合に再度通す。
- ページ変更や通信断では既存イベントをむやみに消さず、記録済みの結果を保持する。

## 巡回進捗の定義

- `nationalDirectoryStationPagesChecked` ≒ 名簿で調査した駅。成功・取得不可は別に記録。
- `homepage候補にアクセスした駅` = 実際にサイトへアクセスを試みた駅。公式運営主体の確定数ではない。
- `strict event probe` = 駅の告知候補を詳細に調べた数。
- `published events` = 保存済み `data/road_events.json` の正規登録イベントのみ。
- 1,234駅の母数と各実測値は `docs/STATION_12_DAY_BOOTSTRAP_STATUS.md` に保存する。

## 継続・リトライ・例外

- 全駅名簿巡回終了後も未調査・読み取り不能・誤表記駅は要確認リストに残す。
- 既訪問のイベントサイトは少なくとも7日間隔をあけて再確認できる。新規サイト優先で、定期再確認の頻度は巡回残数の影響を受ける。
- サイトのrobots規約拒否や取得失敗を「イベントなし」とは表記しない。
- 全国名簿ページが一時的に変化して内容を得られなくても、保存済みのカーソルを保ち、サイト・イベント調査を可能な限り続行する。
- 発表直前の告知、画像だけのチラシ、SNSのみの告知、日時が省略された案内は取り逃しを許容する。
- 大幅なサイト構成変更・掲載中止の反映・駅ごとの公式主体の確認は継続改善課題。全自動で完全なキャンセル反映を保証しない。

## 利用者側

PWAの「気になる場所」または「今日の走り方」→「イベント情報を更新」で、`data/road_events.json` を取得する。端末はローカルに保存し、開催日が過去となったデータを表示対象から除外する。イベント情報の更新はアプリ本体や駅位置DBの更新とは独立。
